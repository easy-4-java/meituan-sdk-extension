## `meituan-sdk-extension` 覆盖审计

审计目标：`/Users/wandl/workspaces/workspace-github-easy-4-java/meituan-sdk-extension`，分支 `feature/3.0.x`。

审计口径：

- API 覆盖必须同时存在官方 `MtOpJavaSDK` Request、`MeituanRetailService` 强类型门面方法及其实现。
- 消息覆盖必须能够解析公共参数、验证签名、按 `msgType` 识别，并生成官方规范响应；具体业务 JSON 的落库或业务动作属于使用方职责。
- 清单没有文档链接、接口路径或 `msgType` 时，不使用中文名称猜造协议。

### 结论

| 范围 | 清单数量 | 审计结果 | 说明 |
| --- | ---: | --- | --- |
| 有文档链接的 API | 90 | 已覆盖 | 均能映射到 businessId=59 的官方 Request 与 `MeituanRetailService` 门面方法；现有 `MeituanApiCoverageTest` 还会扫描官方 SDK 全部 `@ApiMeta` Request，防止门面漏项。 |
| 无文档链接的 API | 5 | 1 项确定覆盖，2 项候选映射，2 项无法确认 | 见下表；缺少官方路径/参数时不应伪造 Request。 |
| 有文档链接的消息 | 33 | 已补齐通用接入层 | 新增消息目录、form 解码、签名验签、`msgType` 路由识别和标准响应模型。 |
| 无文档链接的消息 | 1 | 仅登记，无法路由 | “消费流水变更”没有 `msgType` 和协议文档，目录中保留名称但不填虚假编号。 |

### 新增的消息接入能力

| 类 | 作用 |
| --- | --- |
| `MeituanBusiness59MessageType` | 在独立的 `callback.business59` 命名空间登记 33 项具有官方 `msgType` 的协议，并校验 `businessId=59`；缺少协议的 1 项仅保留在本文清单中。 |
| `MeituanCallbackParser` | 解析官方 `application/x-www-form-urlencoded` 公共参数，保留原始 `message` JSON。 |
| `MeituanCallbackSigner` | 按美团规则生成/验证 SHA-1 签名，并使用常量时间比较签名。 |
| `MeituanCallbackMessage` | 提供与业务无关的公共参数和原始 `message` JSON；businessId=59 目录由独立 resolver 解析。 |
| `MeituanCallbackResponse` | 生成 `{code, message, data}` 标准响应对象。 |

## 剩余边界

- “快速改价”“门店+客户搜索接口”“指定条件分页查询套餐”“打开或关闭预约开关”以及“消费流水变更”仍需要美团侧提供接口路径、参数定义或消息 `msgType` 后，才能确认候选映射或实现并验证。
- 本次完成的是 SDK 出站 API 与入站消息协议层覆盖；具体消息触发的订单、会员、库存等领域动作仍应在业务服务中分别实现并做联调验收。
- “已开通”是美团控制台权限状态，不等于生产环境已经完成真实调用或回调验收。
